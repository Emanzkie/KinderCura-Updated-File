# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

KinderCura is a pediatric developmental-screening system: parents screen their children, pediatricians review results and run appointments, secretaries handle scheduling and cashiering, and admins manage users, clinics, payments, reports and the ML model. Node.js + Express + Mongoose (MongoDB Atlas) backend, plain HTML/JS frontend (no build step), Python scikit-learn ML pipeline. Deployed on Vercel. `README.md` and `READ THESE GUIDES JUSKOLORD/HOW_TO_RUN.txt` are outdated (the latter still describes SQL Server). Ignore them, and ignore `database/*.sql`.

Read `PROJECT_MAP.md` before exploring the code. It lists the stack, the folders, and the key files for each of the four research objectives. Don't rescan the whole project unless you're asked to. `OBJECTIVE_SOURCE_CODE_REPORT.md` contains verified code excerpts for the manuscript.

## Commands

```bash
npm install
npm start                 # node server.js on http://localhost:3001 (PORT overrides)
npm run dev               # same, with nodemon
npm test                  # runs the unit test chain listed in package.json
node tests/unit/<name>.test.js   # run a single test file
npm run test:ml           # Python ML tests (Python 3.12, deps in requirements.txt / ml/requirements.txt)
```

- `.env` needs `MONGODB_URI` (required, there is no localhost fallback) and `JWT_SECRET`. See `.env.example` for email, PayMongo, Blob/R2, and ML service variables. `GET /api/health` reports which required variables are set.
- **Local dev and production use the same Atlas database.** Scripts under `scripts/` (migrations, backfills, seeds, `demo:*`) write to live data. Run the `:dry` / `--dry-run` variant first.
- Tests are plain Node scripts that use `assert`. There's no test framework, no DB and no network: they set `mongoose.set('bufferCommands', false)` and stub model methods in memory, and they blank `EMAIL_USER`/`EMAIL_PASS` before requiring routes. Copy that pattern for new tests. `npm test` is an explicit `&&` chain, so **a new test file must be added to the `test` script in `package.json`**. About 19 files under `tests/unit/` are not in the chain, including most `ml-*` tests and several admin display tests. Run those directly.

## Architecture

**One Express app, two entry points.** `server.js` builds the app. Run directly, it listens on 3001. On Vercel, `api/index.js` requires it and exports the app, and `vercel.json` routes everything except `/api/py/*` to that function. `IS_VERCEL` in `server.js` adds a 9.5 s safety timeout and a lazy `connectDB()` (`db.js` caches the connection on `global`). SSE (`sse.js`, `/api/admin/sse`, used by `js/admin/admin-analytics.js`) only works locally and returns 501 on Vercel, so nothing may depend on it. Pages refresh by polling with `KC.poll` in `api.js`. Any new top-level folder or root file the browser loads must also be added to `includeFiles` in `vercel.json`, or it will be missing in production.

**Static serving and its security guards.** Role pages are flat `.html` files in `PARENT/`, `PEDIA/`, `ADMIN/`, `SECRETARY/` and `SIGN-UP,LOGIN/`. They're served at `/parent/:page`, `/pedia/:page`, `/admin/:page` and `/secretary/:page` by `servePage()`, which only accepts `^[A-Za-z0-9_-]+\.html$`. Clean URLs without `.html` (like `/parent/payment`) need an explicit route registered above the `:page` route. The project root is also statically served, which is how `/api.js`, `/notifications-card-ui.*` and `/constants/scoring.js` reach the browser. `SERVER_ONLY_DIRS` / `SERVER_ONLY_FILES` block backend source and `private/`. If you add a server-only top-level folder or root `.js` file, add it to those patterns. `tests/unit/page-route-traversal.test.js` and `static-cache-headers.test.js` cover this behaviour. Unknown `/api/*` paths return a JSON 404. Other unknown GETs fall back to `landing.html`.

**Backend layout.** Each `routes/*.js` file is mounted in `server.js` under `/api/<name>` (`routes/api.js` is a stale, unmounted leftover). Routes call Mongoose models directly. `services/` holds shared logic (file storage, payments/PayMongo, email, assessment progress, admin report views), and `controllers/` covers only guardians, audit and payments. Auth is a JWT in `Authorization: Bearer`, valid for 48h, verified by `middleware/auth.js`, which sets `req.user` (`role` is one of `User.role`'s enum values: parent, legal_guardian, foster_parent, court_appointed, pediatrician, secretary or admin). Role guards are `adminOnly` and `secretaryOrPediatrician`. A secretary is linked to one pediatrician (`linkedPediatricianId`), and routes must check that link themselves. A child's records are reachable by its parent (`Child.parentId`) or by an active `GuardianLink` with per-permission flags (`middleware/guardianAccess.js`, `guardianPermission.js`). Any route that takes a `childId` or `assessmentId` must check access to *that* child. `tests/unit/child-record-isolation.test.js` documents past breaks.

**Frontend conventions.** There's no bundler. Each page includes `<script src>` tags in order: `/api.js` (shared globals: `window.API`, `window.KC` localStorage session, `apiFetch`, `requireAuth`, nav/avatar init, the single shared notification-bell controller and `notificationDestination`), `/js/shared/mobile-nav.js`, `/notifications-card-ui.js`, then its own `/js/<role>/<page>.js`. Page scripts are classic scripts sharing one global scope, so never redeclare `api.js` functions (especially the bell functions) in a page script. Every `kc_*` localStorage key must be listed in `KC.clear()`. CSS lives in `CSS files/`, served at `/css`, and colours come from the tokens in `kc-tokens.css`. Icons are PNGs in `ICONS/`, served at `/icons`. `views/*.ejs` are served at the deprecated routes `/parent/invite-guardian` and `/admin/guardian-management`, which no page links to (`/parent/guardians` replaced them). `client/*.jsx` is not wired into anything.

**Code shared between browser and server.** `constants/scoring.js` is UMD (`module.exports` and `window.KCScoring`) and is the single source of truth for score bands, labels and colours (see `docs/SCORING.md`). Other `constants/` modules (developmental staging, dataset questions, legal consent) are server-side.

**Static asset caching.** CSS and JS get `s-maxage` of one year on Vercel's CDN, which is purged on deploy, but browsers keep them for 10 minutes and may then run them stale for up to a day. So every page is sent through `sendHtml` in `server.js`, which uses `services/assetVersions.js` to append `?v=<content hash>` to each local `.css`/`.js` URL. A changed file always gets a new URL, and nothing needs bumping by hand. Don't write `?v=` in page HTML. Serve any new page through `sendPage`/`sendHtml` rather than `res.sendFile`. The exception is a CSS `@import`, which isn't rewritten: the three `kc-tokens.css` imports carry the version by hand, and `tests/unit/asset-versions.test.js` prints the expected URL when one goes stale.

**Uploads.** `services/fileStorage.js` writes to local `uploads/` by default. With `USE_BLOB=true` it writes to a private object store (Cloudflare R2 via `services/objectStore.js`, or legacy Vercel Blob via `BLOB_READ_WRITE_TOKEN`) under the same relative path, and `staticFallback` streams misses from the store. Sensitive files (PRC IDs, payment proofs, datasets) are only streamed to admins after a route-level auth check.

**ML pipeline.** `ml/model_manager.js` bridges Node to Python. It spawns local Python (`ml/trainer.py`, `ml/predict.py`) when `USE_LOCAL_PYTHON=true` or off Vercel without `ML_SERVICE_URL`. Otherwise it calls the Vercel Python functions `api/ml_train.py` and `api/ml_predict.py` (`/api/py/train`, `/api/py/predict`) using `ML_SERVICE_SECRET`. Trained models are tracked in `TrainedModel` with activation and rollback, and datasets in `TrainingDataset`. `constants/syntheticData.js` defines how synthetic demo records (from `npm run demo:*`) are marked and purged, and they must stay separable from real records. `constants/dataOrigin.js` defines the three screening-question origins (`CORE_BANK`, `DATASET_QUESTION`, `PEDIA_ENTRY`), which must never be merged.

**Payments.** Booking an appointment is separate from paying for it. The parent picks walk-in or e-wallet on `/parent/payment`. E-wallet proofs are verified on the admin payments page, and PayMongo webhooks hit `/api/payments/webhook/*`, whose raw body is kept for HMAC verification (see the `express.json` `verify` hook). `Appointment.clinicId` records the pediatrician's clinic (`User.clinicId`) at booking time, so a later clinic change never re-attributes the visit, which matters for per-clinic transactions in `routes/admin-clinics.js`. `Appointment.totalAmount` stores the pediatrician's `consultationFee` at booking time.

`docs/` contains design notes for scoring, pediatrician reports, dataset questions, synthetic data and migrations. `graphify-out/GRAPH_REPORT.md` is a generated knowledge graph of the codebase, and `mongodump-kindercura/` is a DB snapshot. Neither is used at runtime.
